# Deploying the public demo

The demo runs on [Render](https://render.com)'s free tier from the `render.yaml` blueprint in the repository root. It holds **synthetic data only**: no sign-up is needed to look around, and nothing real should ever be entered.

## Why this setup costs nothing

- **One free web service, built from the Dockerfile.** The image installs the locked dependencies, trains the forecast model on synthetic patients at build time, runs `alembic upgrade head` on start and serves on Render's `$PORT`.
- **No database service.** `GBA_DEMO_MODE=true` rebuilds the two demo accounts every time the app starts, so nothing has to survive a restart and a SQLite file in `/tmp` is enough. (Render's free PostgreSQL expires after 30 days; this avoids it.)
- **No LLM by default.** The assistant page says it is not set up. To show it live, add `GBA_LLM_PROVIDER=claude` and `GBA_ANTHROPIC_API_KEY` in the Render dashboard and set a monthly spending limit on the API key; the app also limits each user to 30 questions per 10 minutes.

## Steps

1. Push the repository to GitHub.
2. In Render choose **New > Blueprint**, pick the repository and confirm. Render reads `render.yaml`, generates `GBA_SECRET_KEY` and builds the image.
3. When the deploy is live, open the URL and press **Pump + CGM** or **Pens + glucometer**.
4. Put the URL in the README's "Try the demo" line.

## What to expect on the free tier

- The service sleeps after about 15 minutes without visitors; the first request after that takes up to a minute while it wakes (and rebuilds the demo accounts, which takes about a second).
- Visitors share the two demo accounts and can see each other's test entries until the next restart. The banner on every page says so.
- Reminders and push are off in the demo (no VAPID keys); the scheduler still runs in the one process.

## Settings used

| Variable | Value | Why |
|---|---|---|
| `GBA_ENVIRONMENT` | `production` | HTTPS-only cookie, HSTS, refuses the development secret key |
| `GBA_SECRET_KEY` | generated by Render | signs the login cookie |
| `GBA_DATABASE_URL` | `sqlite:////tmp/gba.db` | throwaway database, rebuilt on start |
| `GBA_DEMO_MODE` | `true` | demo buttons, banner, rebuild on start, no deleting demo accounts |
| `GBA_TRUST_PROXY` | `true` | Render's proxy sets `X-Forwarded-For`; the rate limits need the real address |
| `GBA_LLM_PROVIDER` | `none` | no cost; switch to `claude` to show the assistant |

## Running the same container elsewhere

Any host that runs a Docker image works (Fly.io, Railway, a small VPS). Set the variables above; on a host without a proxy in front, leave `GBA_TRUST_PROXY` off. For a real (non-demo) install with your own data, use `docker compose up --build` with PostgreSQL instead, on a machine you control.
